## 一、架构总览

### 当前架构（v2.x）

```
browser → nginx:80 ─┬→ /api/* → refresh_server.py:8081 → news.db
                     ├→ /refresh → refresh_server.py → fetcher.py
                     ├→ /img-proxy → refresh_server.py → external
                     └→ / → static files (index.html, sw.js)
```

### 目标架构（v3.0）

```
browser → nginx:80 ─┬→ /api/* → refresh_server.py:8081 → news.db
                     ├→ /refresh → refresh_server.py → fetcher.py
                     ├→ /img-proxy → refresh_server.py
                     ├→ /auth/* → web_server.py:8082 ─┬→ raynews.db
                     ├→ /favorites/* → web_server.py  │   (users, favorites,
                     ├→ /ai/* → web_server.py         │    ai_configs, settings)
                     ├→ /settings/* → web_server.py   ┘
                     └→ / → static files (frontend/)
```

**关键决策：** 新增一个 Flask Web 服务 `web_server.py`，与现有 `refresh_server.py` 并行运行。两者共用同一个 nginx 反代，通过不同路径前缀分发。这样新闻抓取管道完全不动，只新增用户功能层。

## 三、数据库设计

### 新增 `raynews.db`（独立于现有 `news.db`）

```sql
-- 用户表
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    email TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    nickname TEXT NOT NULL DEFAULT '',
    role TEXT NOT NULL DEFAULT 'user'
        CHECK(role IN ('preview', 'user', 'admin')),
    avatar_url TEXT DEFAULT '',
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 收藏夹
CREATE TABLE favorites (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    article_id INTEGER NOT NULL,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE(user_id, article_id)
);

-- AI API 配置（每个用户可配置自己的）
CREATE TABLE ai_configs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL UNIQUE REFERENCES users(id) ON DELETE CASCADE,
    provider TEXT NOT NULL DEFAULT 'openai',
    api_key TEXT NOT NULL DEFAULT '',
    endpoint TEXT NOT NULL DEFAULT 'https://api.openai.com/v1',
    model TEXT NOT NULL DEFAULT 'gpt-4o-mini',
    enabled INTEGER NOT NULL DEFAULT 0
);

-- 用户设置
CREATE TABLE user_settings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL UNIQUE REFERENCES users(id) ON DELETE CASCADE,
    auto_translate_title INTEGER NOT NULL DEFAULT 0,
    auto_translate_content INTEGER NOT NULL DEFAULT 0,
    daily_summary_enabled INTEGER NOT NULL DEFAULT 0
);
```

## 六、关键设计决策详解

### 6.1 为什么新增 Flask 而非扩展 http.server

| 对比维度 | 继续用 http.server | 切换 Flask |
|----------|-------------------|------------|
| 路由组织 | 手动 `if path == ...` 膨胀 | `@app.route()` 清晰的模块化 |
| 请求体解析 | 手动 `self.rfile.read()` | `request.json` 自动解析 |
| CORS | 手动写 header | `flask-cors` 一行搞定 |
| 文件上传（头像） | 手动解析 multipart | `request.files` 原生支持 |
| Session/JWT | 手动管理 | 成熟扩展 |
| 测试 | 无框架支持 | `app.test_client()` |

**结论：** Flask 是这类功能集的正确选择。refresh_server.py 保持原样不动（新闻管道不需要改），新功能全走 Flask。

### 6.2 JWT vs Session

选择 **JWT（JSON Web Token）**：
- 无状态，方便前端 SPA 管理
- 存储在 `localStorage`，每次请求通过 `Authorization: Bearer <token>` 头传递
- 失效策略：短时效（24h）+ 前端 401 时跳转登录

### 6.3 AI 调用抽象层

```python
# ai_service.py — 统一接口
class AIProvider:
    def __init__(self, config: AIConfig):
        self.endpoint = config.endpoint.rstrip('/')
        self.api_key = config.api_key
        self.model = config.model

    def summarize(self, article_text: str, max_length: int = 200) -> str:
        """生成文章摘要"""
        ...

    def translate(self, article_text: str, target_lang: str = 'zh') -> str:
        """生成双语对照翻译"""
        ...

    def daily_summary(self, articles: list[dict]) -> str:
        """生成每日新闻总结"""
        ...
```

协议：OpenAI 兼容 API（`/v1/chat/completions`），覆盖 OpenAI、Claude、DeepSeek、Ollama 等。

### 6.4 Preview 用户限制实现

前端层面硬限制 + 后端验证：

```js
// 前端拦截
if (user.role === 'preview') {
    document.querySelector('.refresh-btn').style.display = 'none';
    // 禁用下拉刷新
    document.removeEventListener('touchstart', pullRefreshHandler);
    // 禁用翻页按钮
    document.querySelectorAll('.page-btn').forEach(b => b.style.display = 'none');
    // 只显示最新页（page=1）
    currentPage = 1;

```

后端层面所有敏感 API 加 `@require_role('user', 'admin')` 装饰器，preview 用户调用返回 403。

### 6.5 头像方案

- 用户上传头像 → 保存到 `data/avatars/{user_id}.jpg` → nginx 直接 serve `/avatars/{user_id}.jpg`
- 无上传时使用 Gravatart：`https://www.gravatar.com/avatar/{md5(email)}?d=mp&s=80`
- 前端显示优先级：上传头像 > Gravatar > 默认首字母图标

### 6.6 收藏夹与新闻数据的关系

收藏夹只存 `user_id` + `article_id`，完整的文章数据（标题、来源、时间等）通过 `GET /api/news/{id}` 获取。收藏夹列表的渲染：

```
GET /favorites → [{id, article_id, created_at}, ...]
  → 并行 fetch /api/news/{id} 获取每篇文章详情
  → 渲染列表（同首页新闻列表样式）
```

### 6.7 Docker 多进程方案

方案 A（推荐）：**supervisord**
```dockerfile
RUN apt-get install -y supervisor
COPY supervisord.conf /etc/supervisor/conf.d/
# 管理两个进程：nginx + refresh_server.py + web_server.py
```

方案 B：**后台线程 + 独立进程**
在 web_server.py 中通过 `subprocess.Popen` 启动 refresh_server.py。

方案 A 更通用、更可靠。

### 6.8 通知推送模块（notifier.py）

**触发时机：**
- 每日总结生成完毕 → 自动推送到用户的已配置渠道
- 手动触发（用户点击"发送到手机"按钮）

**配置存储：**
`user_settings` 表新增 `notification_config` TEXT 字段，存 JSON：

```json
{
  "bark": { "url": "https://api.day.app/xxx" },
  "smtp": {
    "host": "api.resend.com",
    "port": 587,
    "user": "xxx@example.com",
    "pass": "******",
    "to": "user@example.com"
  }
}
```

**notifier.py 设计：**

```python
class Notifier:
    def send_bark(self, title: str, body: str, url: str) -> bool:
        """通过 Bark API 推送到 iPhone"""
        requests.post(config["bark"]["url"], json={
            "title": title,
            "body": body,
            "sound": "default",
            "url": url  # 点击推送打开 RayNews
        })

    def send_email(self, subject: str, html_body: str, smtp_config: dict) -> bool:
        """通过 SMTP 发送邮件"""
        ...

    def send(self, channel: str, title: str, body: str, url: str = ""):
        """统一入口，根据 user_settings.notification_config 分发"""
        if channel == "bark" and config.get("bark", {}).get("url"):
            self.send_bark(title, body, url)
        if channel == "smtp" and config.get("smtp", {}).get("host"):
            self.send_email(title, body, config["smtp"])
```

**安全考虑：**
- SMTP 密码存数据库是必要的取舍（自部署场景）
- Bark URL 本身就是 token，无需额外加密

### 7.2 全局状态管理

```js
// 新增全局状态对象
const state = {
    user: null,          // { id, email, nickname, role, avatar_url }
    token: null,         // JWT token string
    favorites: new Set(), // Set<article_id> — 快速判断是否已收藏
    aiConfig: null,      // { provider, api_key, endpoint, model, enabled }
    settings: null,       // { auto_translate_title, auto_translate_content, ... }
};

// 持久化
function saveAuth(token, user) {
    localStorage.setItem('raynews_token', token);
    localStorage.setItem('raynews_user', JSON.stringify(user));
    state.token = token;
    state.user = user;
}

function loadAuth() {
    state.token = localStorage.getItem('raynews_token');
    try { state.user = JSON.parse(localStorage.getItem('raynews_user')); } catch {}
}
```

### 7.3 API 请求封装

```js
async function apiFetch(url, options = {}) {
    const headers = options.headers || {};
    if (state.token) {
        headers['Authorization'] = 'Bearer ' + state.token;
    }
    const resp = await fetch(url, { ...options, headers });
    if (resp.status === 401 && state.token) {
        // Token expired — redirect to login
        logout();
        showLoginModal();
        return null;
    }
    return resp.json();
}
```

## 八、风险与注意事项

### 风险点

1. **SQLite 并发写**：多个用户操作可能同时对 `raynews.db` 写操作。SQLite 的 WAL 模式允许并发读，但写操作串行。对于个人/小团队使用场景（< 50 用户），这不是问题。

2. **AI API Key 安全**：用户的 API Key 存储在服务端数据库。虽然不是最佳实践（用户本地存储更安全），但考虑到这是一个自部署应用，API Key 存服务端是合理取舍。

3. **Preview 用户绕过限制**：前端禁用按钮防君子不防小人，后端 API 验证才是真正的限制。

4. **大版本迁移**：从 v2.x 到 v3.0 涉及数据库 schema 变更和容器架构变化，建议有降级方案或快照。

### 不做的事（Scope）

- ❌ OAuth/第三方登录（暂不做，留接口后续可加）
- ❌ 多语言前端界面
- ❌ 关注、评论、点赞等社交功能（已有链接分享，够用）

### Phase 4 包含：通知推送（Bark / SMTP）

**已纳入 Phase 4 实现，非后续规划。**

**场景：**
- 用户配置 Bark URL → 每日总结生成后自动推送到 iPhone
- 用户配置 SMTP → 每日总结定时发送到邮箱
- 未来可扩展：新文章推送、收藏文章更新通知

**实现方案：**
- `user_settings` 表增加 `notification_channels` JSON 字段（存储 Bark URL / SMTP 配置）
- `notifier.py` 独立模块，支持 Bark API / SMTP 插件化
- `ai_service.py` 的 `daily_summary` 完成时自动触发通知
- 支持定时（cron 风格）和手动触发两种模式
