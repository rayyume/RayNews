# 管理员通知邮件 Markdown 排版设计

## 问题与目标

每日摘要邮件已经将 Markdown 转成 HTML；管理员广播邮件却无条件转义正文，因此 `####`、`**`、列表和图片语法会原样显示。目标是让管理员选择 Markdown 时，站内通知与邮件都按相同语义排版，同时保持纯文本及普通系统告警邮件的现有行为。

## 数据流

管理员广播路由继续保存原始正文与 `plain|markdown` 格式。后台邮件 fan-out 将已提交的格式传递给 `_send_notification_email()`。该函数默认 `plain` 以兼容所有现有调用方；仅广播的 Markdown 邮件进入服务端 Markdown 渲染路径。

## 渲染与安全

- 使用项目已有的 Python Markdown，启用 fenced code、tables 等既有扩展。
- Markdown 转换结果必须经过 BeautifulSoup 标签/属性白名单清洗；移除脚本、样式、事件属性、iframe、表单及危险协议。
- 允许常用标题（h1-h6）、段落、强调、列表、引用、代码、表格、链接和图片。
- 链接仅允许 http/https，增加安全的链接属性。
- 图片仅允许公网 http/https 原地址，并改写为基于 `RAYNEWS_PUBLIC_URL` 的绝对 `/img-cache?url=...` 地址；无有效公开站点地址或非法图片 URL 时移除图片，不输出危险源地址。
- 纯文本正文继续执行 HTML 转义和换行转 `<br>`。

## 邮件样式与界面提示

通知邮件模板为 h1-h6、p、列表、链接、引用、代码、表格和响应式图片提供内联模板 CSS；邮件标题和页脚保持现状。管理员广播页面提示改为：Markdown 邮件同步显示排版和图片，纯文本模式原样显示。

## 兼容边界

- 每日摘要继续使用现有专用邮件模板，不改变统计信息、主题、发送和幂等逻辑。
- 站内通知渲染、广播原文存储、重试去重、收件人选择及邮件失败告警保持不变。
- `_send_notification_email()` 新增可选格式参数并默认 `plain`，避免系统普通通知被误当作 Markdown。

## 验证

TDD 覆盖 Markdown 标题/列表/链接/代码/表格、图片缓存改写、危险 HTML/协议移除、纯文本原样转义、格式在广播后台线程中的传递，以及现有通知邮件失败和广播幂等回归测试。
