# 通知列表日期与未读操作优化设计

## 目标

提升通知清单的信息密度和未读状态可读性，不改变通知读取、删除或详情页的既有数据语义。

## 日期展示

通知创建时间仅在前端按用户浏览器本地时区格式化：

- 当天：`今天 HH:mm`
- 前一天：`昨天 HH:mm`
- 前两天：`前天 HH:mm`
- 更早：`M-D HH:mm`，例如 `7-26 09:30`

不修改 API 字段、数据库时间或服务端时区。日期在桌面与移动通知行都保留显示，利用精简格式减少对标题空间的占用。

## 未读状态与操作

- 移除通知行中的 `new` 标签；用户菜单入口的未读提示保持现状，不在本次变更范围内。
- 未读通知右侧保留一个状态/操作按钮：静止态显示 `未读`，沿用原 `new` 标签的琥珀色半透明背景和文字色。
- 鼠标悬停或键盘聚焦时，按钮切换为绿色 `已读`，表达点击会执行的操作。
- 点击后沿用现有乐观已读流程：立即标记为已读、未读数同步减少、按钮消失；请求失败时恢复未读状态和按钮。
- 已读通知不显示该按钮，仅保留删除按钮。删除、全部已读、全部删除、通知详情页按钮与接口行为均不变。

## 实现边界

- 只调整 `frontend/index.html` 的通知列表渲染、样式和日期格式化逻辑。
- 复用 `markNotifRead()` 的并发保护、乐观更新和失败回滚；不新增网络请求或状态字段。
- 使用清晰的 CSS 状态：未读按钮文本由伪元素/可访问标签或 DOM 文本在 hover/focus 状态一致切换，触摸设备保持静止态 `未读`，点击仍执行已读。

## 验证

新增或更新前端契约测试，覆盖本地日期边界、较早日期格式、未读标签移除、按钮静止/悬停文案及既有 `markNotifRead()` 调用路径。运行相关通知/UI 测试和完整前端语法检查。
