# 邮件投递失败管理员告警设计

## 目标
当 RayNews 的 Resend 邮件通道不可用时，向所有管理员发送一次站内告警；通道恢复后允许下一次独立故障再次告警。

## 范围
- 检测统一通知邮件入口 `_send_notification_email()` 的两类故障：
  1. `RESEND_API_KEY` 未配置；
  2. 调用 Resend 抛出异常，包括 API Key 无效、网络或服务端错误。
- 首次故障向所有 `admin` 角色用户写入一条站内通知。
- 使用持久化应用状态保存“本轮邮件通道故障已告警”标记，避免进程重启或持续失败产生重复告警。
- 任意一次统一通知邮件成功后清除该标记；之后的新故障可再次告警。

## 非目标
- 不改变原有邮件发送、收件人选择或邮件内容。
- 不修改邀请、注册、历史清理等直接调用 `send_email()` 的独立邮件流程。
- 不发送邮件通道恢复通知。
- 不为单个收件人地址无效单独区分故障类别；该类 Resend 发送异常仍按统一邮件通道故障处理。

## 架构与数据流
1. `_send_notification_email()` 在发现缺少 `RESEND_API_KEY` 或捕获 `send_email()` 异常时，调用新的邮件通道故障记录函数。
2. 记录函数通过应用状态原子声明本轮故障的告警权；只有成功声明的一次会继续通知管理员。
3. 管理员告警直接写入通知表，不经过 `_notify_user()` 或 `_send_notification_email()`，因此不会因告警邮件再次失败而递归。
4. 任意 `_send_notification_email()` 成功后清除持久化标记。持续故障期间的后续失败均被抑制；恢复后的下一次失败重新产生一次告警。

## 通知内容
- 类型：`email_delivery_failed`
- 标题：`邮件推送服务不可用`
- 正文说明邮件投递失败、简短原因（对异常压缩为最多 300 字符），并提示管理员检查 `RESEND_API_KEY`、Resend 账户状态及 `RAYNEWS_FROM_EMAIL` 配置。
- 通知仅写入站内，目标为所有管理员，不发送邮件。

## 错误处理
- 告警写入、应用状态读取或更新失败不得改变原始邮件失败的 best-effort 语义，也不得向调用方抛出异常。
- 若无法确认或写入持久化状态，优先尝试一次站内告警，而不是静默丢失故障信号。
- 邮件发送成功后的状态清理失败只记录日志；不会将成功发送改为失败。

## 测试
新增针对真实通知入口的自动化测试，覆盖：
1. 缺少 `RESEND_API_KEY` 时，首次失败为每位管理员创建一条站内告警；
2. 相同持续故障不会重复创建告警；
3. Resend 发送异常的首次失败触发相同告警；
4. 一次成功发送清除抑制标记，随后的新失败可再次告警；
5. 管理员告警不调用邮件发送入口，证明无递归。
