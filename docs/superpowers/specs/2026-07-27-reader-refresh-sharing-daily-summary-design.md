# RayNews 图片、刷新计数、共享恢复与每日摘要设计

**日期：** 2026-07-27  
**目标分支：** `dev`  
**状态：** 已确认，待编写实施计划

## 1. 背景与目标

本设计覆盖四个可独立测试、独立提交的子项目：

1. 统一文章封面、正文和翻译后图片的全屏查看行为，并在移动端全屏查看器中支持双指缩放与拖动。
2. 将手动刷新时快速出现的存量新文章与本轮抓取的新文章统一纳入同一个去重计数，使刷新按钮与完成提示一致。
3. 将共享 API 失效后的行为由“关闭共享并遗失用户选择”改为“暂停共享并保存用户意愿”，在 API 恢复后自动恢复并通知用户。
4. 取消普通用户手动生成每日摘要，改为北京时间 21:00 由服务端系统 API 生成一份全局摘要，再按用户设置分发至站内通知和邮箱。

本次采用增量改造，不对 `frontend/index.html` 或 `web_server.py` 进行与需求无关的大规模拆分。每个子项目都必须保持现有访问和刷新关键路径性能。

## 2. 已确认的产品规则

### 2.1 图片查看

- 文章详情中的封面图、正文图片以及翻译后动态插入的图片均可点击进入同一个全屏查看器。
- 移动端的验收口径是：先点击图片进入全屏，再支持双指缩放和放大后拖动。
- 不要求未进入全屏时直接在正文中双指缩放。
- 全屏查看器关闭后必须保持文章原滚动位置，并清除上一次缩放和位移。

### 2.2 刷新计数

- 刷新计数统计所有来源、所有分类的新文章，不受当前首页分类影响。
- 快速增量和本轮抓取结果按文章 ID 去重。
- 刷新按钮与完成 Toast 使用同一个累计去重数量：
  - 大于零：`✅ 更新完成，新增 N 篇文章`
  - 等于零：`✅ 已是最新`
- 不允许通过将两个计数直接相加来猜测总数。

### 2.3 共享暂停与恢复

- 用户此前开启共享后，API 校验失败只暂停共享，不清除总开关和三个查看子开关。
- 暂停时总开关保持选中并标注“已暂停”；三个子开关保留原选择但暂时禁用。
- 暂停期间用户不得读取服务端共享的标题翻译、文章翻译或文章摘要。
- 以下任一路径校验成功后自动恢复：
  - 保存新的个人 API 配置后的即时测试；
  - 用户手动执行 API 连接测试；
  - 后台定期复测。
- 恢复时原样恢复失效前的三个子开关选择，无需用户再次开启共享。
- 暂停和恢复各在状态发生跃迁时通知一次，渠道为站内通知和邮件。
- 用户主动关闭共享后，不得因后续 API 恢复而自行重新开启。

### 2.4 每日摘要

- 北京时间每天 21:00 只使用管理员配置的服务端系统 API 生成一份全局摘要。
- 用户数量不得增加 AI 调用次数；所有用户看到和接收的都是同一份摘要。
- 普通用户不再拥有生成、重新生成或重试入口。
- 自动生成失败后停止自动重试。
- 失败时只向管理员发送站内通知和邮件，列明安全分类后的原因；普通用户不接收失败推送。
- 管理员的“重试生成”按钮仅在当天服务端生成状态为 `failed` 时可点击：
  - 21:00 前、生成中、成功后均不可点击；
  - 提交重试后立即禁用；
  - 后端必须再次校验管理员身份和 `failed` 状态。
- 生成成功后：
  - 首页右上角 ✨ 打开并展示摘要；
  - 根据独立设置写入用户站内通知；
  - 根据独立设置发送摘要邮件。
- 21:00 前 ✨ 弹窗显示：

  > 每日摘要将在北京时间每天晚 9 点（21:00）生成显示

- 21:00 前弹窗提供“每日摘要推送设置”按钮，跳转至 `用户设置 → 通知`。
- 站内通知详情展示完整 Markdown 摘要，其中的文章链接在站内打开文章详情。
- “每日摘要站内推送”：
  - 现有用户默认开启；
  - 新用户默认开启；
  - 不补发上线前的历史摘要。
- 现有“每日摘要推送”重命名为“每日摘要邮箱推送”：
  - 现有用户保留原开关和邮箱；
  - 新用户默认关闭；
  - 未填写接收邮箱时不得启用。
- 关闭站内推送只影响通知清单，用户仍可通过首页 ✨ 查看当天摘要。

## 3. 现状与根因

### 3.1 顶部图片不能进入全屏

`openArticle()` 将 `thumb` 封面插入 `#articleBody` 之前，而 `renderArticleBody()` 只对 `bodyEl.querySelectorAll('img')` 绑定点击事件。因此封面不在绑定范围内。翻译切换和自动展示翻译还存在多处重复的图片点击绑定，其中部分路径没有统一执行滚动锁定和缩放初始化。

### 3.2 快速出现的新文章未计入按钮

`triggerRefresh()` 并行启动 `loadSince(..., { manual: true })` 和抓取任务。前者会快速显示数据库中已存在、当前会话尚未见过的文章；刷新按钮则只读取抓取任务状态中的 `new_count_so_far`。两条数据流没有共享同一个计数来源，直接相加又会在并发抓取时重复计算同一文章。

### 3.3 共享无法自动恢复

`_run_ai_share_revalidation_once()` 在校验失败时将 `share_ai_results` 和三个 `share_view_*` 字段全部清零。随后该用户不再出现在 `get_users_with_share_enabled()` 的复测集合中，系统既遗失了用户原选择，也没有后续恢复触发点。

### 3.4 每日摘要仍可手动触发且生成依赖邮件条件

前端仍包含 `generateDailySummary()` 和生成/重新生成按钮，后端仍允许普通用户 `POST /ai/daily-summary`，并可使用用户个人 API 生成用户级摘要。现有 21:00 调度入口 `_broadcast_daily_summary()` 会在未配置 Resend、没有邮箱订阅者或没有收件邮箱时提前返回，导致全局摘要本身也不生成。生成成功后只处理邮件，未写入站内通知。

## 4. 总体架构

四个子项目按以下边界实现：

1. **图片查看器：** 前端单一事件委托和单一手势状态机。
2. **刷新计数：** 抓取进度携带文章 ID，前端为每次刷新维护独立 ID 集合。
3. **共享恢复：** 用户意愿字段与运行时暂停字段分离，所有共享读取统一校验有效状态。
4. **每日摘要：** 全局生成状态、全局摘要内容、站内分发、邮件分发四层分离。

不得把上述四个子项目混为一个不可回滚的大提交。实施计划应形成四份计划或四个明确阶段，每阶段独立运行相关测试并提交。

## 5. 详细设计

### 5.1 统一图片查看器

#### 5.1.1 事件边界

- 在 `#articleWrap` 上注册一次点击事件委托。
- 仅当 `event.target.closest('img')` 属于 `articleWrap` 时打开查看器。
- 图片地址优先使用 `currentSrc`，回退到 `src`。
- 封面、正文和后续 `innerHTML` 替换出的翻译图片自动继承行为。
- 删除翻译和摘要相关路径中的重复逐图事件绑定。

#### 5.1.2 查看器状态

查看器维护以下会话状态：

- 当前缩放倍数；
- X/Y 位移；
- 当前活动 Pointer；
- 双指初始距离、中心点和初始缩放；
- 是否发生过拖动或缩放，用于阻止手势结束后的误关闭。

每次打开和关闭均调用同一个重置函数。切换文章、退出详情或按 `Escape` 也必须关闭并重置查看器。

#### 5.1.3 手势规则

- 使用 Pointer Events，查看器手势区域设置 `touch-action: none`。
- 双指距离控制缩放，范围固定为 1～4 倍。
- 缩放围绕双指中心点计算。
- 仅当倍数大于 1 时允许单指拖动。
- 位移按当前图片尺寸和视口尺寸限制，避免图片完全拖出屏幕。
- 单击遮罩可关闭；拖动或缩放手势结束不得关闭。
- 桌面端保留点击、关闭按钮和 `Escape`。
- 不再依赖动态修改 viewport meta 来实现图片缩放，避免 PWA 缩放状态残留。

### 5.2 刷新累计去重计数

#### 5.2.1 服务端进度

- `fetcher.py` 在现有 `fetch_progress.json` 中保存当前任务已插入文章的 ID 列表。
- ID 列表与现有 `job_id`、`inserted` 一起原子写入。
- `refresh_server.py` 运行态响应新增 `new_ids_so_far`。
- 终态响应新增由任务开始前后文章 ID 差集计算出的 `new_ids`。
- `new_count_so_far` 和 `new_count` 继续保留，供诊断和旧客户端兼容。
- 状态查询不得为返回 ID 额外扫描数据库；运行态直接读取现有进度文件，终态复用现有 ID 差集。

#### 5.2.2 前端刷新会话

每次 `triggerRefresh()` 创建：

- 唯一流程 generation；
- 独立 `AbortController`；
- `Set<number>` 形式的 `discoveredArticleIds`。

现有 `loadSince()` 保持数字返回值兼容，同时增加可选的发现回调，将本次新增的 `newItems` 交给当前刷新会话。以下数据都加入同一个集合：

- 点击后立即增量检查返回的文章 ID；
- 运行态 `new_ids_so_far`；
- 终态 `new_ids`。

集合发生增长时调用统一的刷新计数渲染函数。流程 generation、controller 或页面生命周期失效后，迟到响应不得再更新集合或界面。

#### 5.2.3 显示与失败降级

- 运行初始状态为“更新中”。
- 集合非空后显示 `+N`，title 为 `已获取 N 篇`。
- 完成 Toast 使用集合最终大小。
- 若某次状态查询缺少 ID 字段，保留最后已确认数量；不得用可能重叠的两个 count 相加。
- 新旧服务短暂混用时仍可完成刷新，只是不会显示未经 ID 确认的累计增长。

### 5.3 共享暂停与自动恢复

#### 5.3.1 数据模型

在 `user_settings` 新增：

```text
share_suspended INTEGER NOT NULL DEFAULT 0
```

字段语义：

- `share_ai_results`：用户是否长期选择参与共享；
- `share_view_title`、`share_view_translation`、`share_view_summary`：用户偏好；
- `share_suspended`：系统是否因 API 校验失败暂停共享；
- `share_last_check_ok`、时间和错误：最近一次校验结果。

共享实际有效条件为：

```text
share_ai_results = 1
AND share_suspended = 0
AND share_last_check_ok = 1
```

该判断必须集中为后端 helper，并在前端标题显示逻辑中使用后端返回的 `share_active` 派生值，避免各路径自行组合字段。

#### 5.3.2 暂停转换

校验从成功变为失败时：

1. 设置 `share_suspended=1`；
2. 更新最后校验时间、结果和安全错误文本；
3. 不修改总开关和三个子开关；
4. 插入一次 `share_suspended` 站内通知；
5. 尝试发送同内容邮件。

连续失败只更新时间和错误，不重复通知。

#### 5.3.3 恢复转换

校验从暂停变为成功时：

1. 设置 `share_suspended=0`；
2. 更新最后校验时间并清除错误；
3. 原有三个偏好立即重新生效；
4. 插入一次 `share_restored` 站内通知；
5. 尝试发送同内容邮件。

未处于暂停状态的连续成功不发送恢复通知。

#### 5.3.4 校验触发

- `PUT /ai/config` 先保存配置；若用户的 `share_ai_results=1`，保存后立即执行连接测试并返回共享恢复结果。
- `POST /ai/test-connection` 成功时执行同一恢复转换。
- 后台定期复测集合包含所有 `share_ai_results=1` 的用户，包括已暂停用户。
- 用户主动将总开关关闭时，三个偏好按现有产品行为关闭，并清除 `share_suspended`；此后不再复测或自动恢复。

#### 5.3.5 UI

- `GET /settings` 返回 `share_suspended` 和派生的 `share_active`。
- 暂停时总开关保持选中，三个子开关保持选中状态但 disabled。
- 状态文案说明“共享已暂停；更新 API 并校验成功后会自动恢复，无需重新开启”。
- 保存新 API 的响应需区分：
  - 配置已保存且共享已恢复；
  - 配置已保存但连接测试失败，共享仍暂停。

### 5.4 每日摘要全局生成与分发

#### 5.4.1 用户设置迁移

`user_settings` 新增：

```text
daily_summary_inapp_enabled INTEGER NOT NULL DEFAULT 1
```

- SQLite 迁移使现有用户获得默认值 1。
- 新用户未创建设置行时，`GET /settings` 默认返回 true。
- 现有 `daily_summary_enabled` 保留并仅表示邮箱推送，默认仍为 0。
- 前端将标签改为“每日摘要邮箱推送”，新增“每日摘要站内推送”。
- 后端保存邮箱推送为开启时必须验证最终设置中存在非空接收邮箱。

#### 5.4.2 全局运行状态

在 `NEWS_DB` 新增 `daily_summary_runs`，以北京时间日期为主键，至少包含：

- `date`
- `status`: `running`、`completed`、`failed`
- `attempt_count`
- `trigger`: `scheduled`、`admin_retry`
- `error_code`
- `error_detail`
- `started_at`
- `finished_at`

运行记录与 `daily_summary_global` 分工：

- `daily_summary_runs` 决定当天是否允许生成或重试；
- `daily_summary_global` 保存唯一摘要正文、文章数和统计信息。

旧的用户级 `daily_summary_cache` 不再读取或写入，但本次不删除表。

#### 5.4.3 21:00 调度

- 调度器使用 `_beijing_now()`。
- 21:00 前不创建当天运行记录。
- 21:00 后若当天不存在运行记录或全局摘要，原子创建 `running` 记录并启动一次后台生成。
- 已为 `running`、`completed` 或 `failed` 时，自动调度不得重复启动。
- 服务在 21:00 后重启且当天从未尝试时，应补做一次；当天已失败则不自动重试。
- 生成不再依赖 Resend 配置、邮箱订阅人数或收件邮箱。

#### 5.4.4 唯一全局生成

- 仅使用 `get_system_ai_config()` 返回的管理员服务端 API。
- 获取当天全部文章并沿用现有去重逻辑。
- 每个北京时间日期最多有一份成功摘要。
- 用户个人 API、用户数量和用户设置不得进入生成调用。
- 成功顺序：
  1. 保存 `daily_summary_global`；
  2. 将 `daily_summary_runs` 标为 `completed`；
  3. 启动站内和邮箱分发。

#### 5.4.5 失败分类

失败至少归入：

- `system_api_not_configured`
- `system_api_auth_or_quota`
- `system_api_model_error`
- `server_network_error`
- `no_articles`
- `generation_error`

`error_detail` 只保存适合管理员查看的压缩、安全文本，不包含 API Key、完整响应体、内部路径或堆栈。

失败顺序：

1. 将运行记录标为 `failed`；
2. 停止当天自动尝试；
3. 仅向所有管理员插入失败站内通知；
4. 尝试向管理员发送同内容邮件。

普通用户不接收失败通知。普通用户在 ✨ 中只看到“今日每日摘要暂未生成，请稍后查看”。

#### 5.4.6 管理员重试

- 新增管理员专用 `POST /ai/daily-summary/retry`。
- 仅允许当天状态为 `failed` 时调用。
- 使用条件更新或锁将 `failed` 原子转换为 `running`，`attempt_count + 1`，`trigger=admin_retry`。
- 并发或重复请求仅一个成功，其余返回 `409 Conflict`。
- 普通用户返回 `403 Forbidden`。
- 重试再次失败时更新错误并再次向管理员通知本次失败；每个 attempt 只通知一次。
- 重试成功后进入正常分发，不允许再重试成功摘要。
- 删除普通用户手动生成入口；旧 `POST /ai/daily-summary` 不再触发生成。

管理员按钮状态：

| 当天状态 | 按钮 |
|---|---|
| 21:00 前 | 显示但禁用 |
| `running` | 显示但禁用 |
| `completed` | 显示但禁用 |
| `failed` | 启用 |
| 重试请求提交后 | 立即禁用 |

普通用户永远不渲染该按钮。

#### 5.4.7 幂等站内分发

`notifications` 新增可空的 `source_key`，并建立仅覆盖非空值的唯一索引：

```text
UNIQUE(user_id, type, source_key) WHERE source_key IS NOT NULL
```

每日摘要通知使用：

- `type = daily_summary`
- `source_key = daily-summary:<YYYY-MM-DD>`
- `format = markdown`

批量插入采用 `INSERT OR IGNORE` 和单事务。同一天重复执行分发不会产生重复通知。通知正文直接保存同一份全局摘要 Markdown。

摘要中的站内文章链接沿用 ✨ 弹窗现有的文章路由规则；通知详情增加同样的链接委托，使文章在站内详情 overlay 打开。

#### 5.4.8 邮箱分发

- 只查询 `daily_summary_enabled=1` 且存在接收邮箱的用户。
- 继续使用按日期和用户持久化的邮件发送状态及 Resend 幂等键。
- 邮件发送失败不改变全局摘要的 `completed` 状态，也不阻止其他用户收到站内通知。
- 未配置 Resend 不得阻止全局摘要生成或站内分发。

#### 5.4.9 今日状态 API 与前端

`GET /ai/daily-summary/today` 返回统一全局状态：

- 21:00 前：`scheduled`
- 生成中：`running`
- 成功：`completed` 和全局摘要
- 失败：`failed`

失败详情仅对管理员返回；同时返回布尔值 `can_retry`，只有管理员且状态为 `failed` 时为 true。

前端不再维护用户级生成 job。✨ 弹窗按全局状态渲染：

- `scheduled`：固定提示和“每日摘要推送设置”按钮；
- `running`：只显示生成中；
- `completed`：显示摘要、生成时间和文章数，无重新生成按钮；
- `failed`：普通用户显示通用提示，管理员显示安全原因和受控重试按钮。

## 6. 性能约束

- 首页初始化不得新增网络请求。
- 手动刷新不得增加轮询次数。
- 刷新 ID 通过现有增量响应、进度文件和状态响应传递，不新增每轮文章列表查询。
- 快速增量应继续在约 1 秒内出现。
- 图片手势计算只在查看器打开且存在活动 Pointer 时运行。
- 共享有效状态只增加常量级字段读取，不在首页请求中执行连接测试。
- 已暂停用户仍参加六小时复测；AI 网络等待期间不得持有数据库事务或写锁。
- 每日摘要生成、站内批量通知和邮件发送均在后台执行。
- 站内通知使用单事务批量插入，邮件发送不得持有数据库写事务。
- 21:00 分发期间 `/api/news` 和 `/auth/refresh/status` 必须保持可响应。

## 8. 验收标准

   ```bash
   python3 -m pytest -q
   ```
