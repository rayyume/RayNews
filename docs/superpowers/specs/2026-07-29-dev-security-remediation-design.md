# Dev 分支安全问题修复设计

## 目标
修复审查发现的首管理员竞争、服务端请求伪造、错误与诊断泄露、认证/邀请码滥用和共享 AI 缓存投毒问题，同时保持正常用户流程不变。

## 范围与体验约束
- 正常公网图片和公网 AI Endpoint 保持可用。
- 局域网、私网、回环、链路本地、保留地址及解析/重定向到这些地址的 URL 会被拒绝。
- 自建内网模型不再受支持；这是已确认的兼容性取舍。
- 用户可继续本地使用个人 AI；只有连通性校验有效的共享用户可以发布共享缓存。
- 错误详情从客户端收敛到服务端日志；正常成功响应不变。

## 设计

### 1. 原子首管理员注册
在模型层提供原子注册操作，在单一 SQLite `BEGIN IMMEDIATE` 事务内检查用户数量并插入用户。仅事务内确认的第一个用户获得 `admin` 角色；并发后到的无邀请码请求按既有邀请码规则失败。既有数据库和后续邀请码注册流程不变。

### 2. 公网 URL 安全校验
新增专用网络安全模块，供图片缓存和服务端 AI 请求共用：
- 仅接受 HTTP/HTTPS、带主机名的 URL；
- 解析 A/AAAA 记录，拒绝 loopback、private、link-local、multicast、reserved、unspecified 地址；
- 不自动信任重定向；逐跳校验目标 URL，并限制跳转次数；
- 图片抓取和 AI relay/连接测试均在发起服务端请求前执行校验。

图片缓存的外部接口继续工作，但对不安全目标返回安全的失败响应。AI 配置保存、relay 与连通性测试均拒绝内网 Endpoint。

### 3. 错误和公开诊断
- Flask 未处理异常及各个外部服务失败分支仅返回通用、安全消息，保留详细异常日志。
- 公共 `/api/meta` 仅返回文章数量；数据目录、数据库路径、抓取输出与频道配置不再公开。
- `/api/news` 当前用于首页冷启动的最小 `refresh_job`/`global_article_count` 诊断字段保留，避免影响首页加载流程。

### 4. 登录和邀请码滥用保护
- 使用持久化限流记录：同一真实客户端 IP 与规范化账号连续失败 5 次后锁定 15 分钟；成功登录清除失败计数。仅在服务端来自受信任的 loopback Nginx 代理时使用 `X-Real-IP`。
- 同一邮箱的邀请码申请在一次成功发送后进入 15 分钟冷却；冷却结束前允许一次新的成功申请，随后再次冷却。邮件发送失败或校验失败不消耗次数。
- 限流响应不透露账号是否存在；前端显示明确的等待时间。

### 5. 共享 AI 缓存授权与来源
- `POST /ai/result/<id>` 仅在调用者的共享状态有效（开启、校验成功、未暂停且配置版本一致）时允许写入。
- 保存摘要/翻译时同时写入作者用户 ID、提供商、模型和生成时间；数据库迁移兼容已有 `ai_results` 表。
- 前端仅在用户共享状态有效时提交结果到共享缓存；本地摘要/翻译显示保持不变。
- 缓存读取的现有共享查看权限保持不变。

## 测试
新增或扩展测试覆盖：
1. 并发首注册仅产生一个管理员；
2. 图片与 AI Endpoint 对私网 IP、DNS 解析结果及重定向目标的拒绝；
3. 公网图片/AI 正常路径保留；
4. 客户端错误响应不含底层异常、公共元数据不含部署诊断；
5. 登录阈值、锁定、成功重置和代理真实 IP；
6. 邀请码首次/冷却/失败发送不消耗额度；
7. 未验证共享用户不能写缓存，已验证用户写入作者、提供商、模型和时间；
8. 全量回归测试。
